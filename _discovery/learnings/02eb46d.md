# Wave 5 Appearance — runtime UI customization (v0.4.962, s232)

UX-overhaul Wave 5 (final). Owner: "start framing up our UI Customization
settings — transitions, spacing, theme management, etc."

## Wave 0c paid off — the radius lever was already runtime-ready
- In Wave 0c I made `--radius-*` tokens `calc(base * var(--radius-scale))` with
  `--radius-scale` defined outside @theme. Wave 5 just sets `--radius-scale` on
  documentElement (1=Subtle / 0.6=Sharp / 0.15=Near-square) and the WHOLE app
  (incl. react-fancy) re-rounds instantly. Building the runtime hook into the
  token system early (even when nothing drove it yet) made the Appearance page a
  thin control layer instead of a refactor. Lesson: when you touch a design token
  for a one-time change, express it as `calc(* var(--scale))` so a future
  settings page is free.

## AppearanceProvider mirrors ThemeProvider
- Same shape: read config on mount → apply CSS vars to documentElement → expose
  a context `update()` that applies live + persists. Persist via the existing
  dot-notation `PATCH /api/config { key:"ui.appearance", value }` (preserves
  siblings; no new endpoint). Defaults live BOTH in the TS (APPEARANCE_DEFAULTS)
  AND in index.css :root so the app renders correctly before the provider's
  fetch resolves (no flash).
- reduce-motion = a `.reduce-motion` class that collapses transition/animation
  durations, PLUS a `@media (prefers-reduced-motion)` rule so the OS preference
  is honored even before any toggle.

## Generic preset-button row
- `PresetRow<T extends string | number>` handles radius (number) + motion/density
  (string unions) with one component; TS infers T from `options`. Cast in the
  string-union onSelect callbacks (`v as Appearance["motion"]`) since TS widens
  the inferred option value to `string`.
